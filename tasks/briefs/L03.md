# L03 — Bigger or More?  (users milestone: 10,000; source: reference/ch1.txt p.8-9 (Vertical scaling vs horizontal scaling))

## Story + lesson content
Incident: 10K users, the lone web server is at 98% CPU. Maya: 'Just buy a bigger server!'. Lesson: scale up vs scale out; vertical's simplicity; hard limit (can't add unlimited CPU/RAM); no failover/redundancy (one box dies -> whole site down); why large apps prefer horizontal; direct connection problems (offline server = no site, overload = slow/failing). Ends teasing the load balancer.

## Lab
Lab: an 'Upgrade' slider (CPU/RAM tiers, cost rises steeply) hits a hardware wall; a 'Kill server' button shows total outage; compare with adding 2 small servers (still no LB -> users stuck on one IP).

## Mini-games
MiniGame 'Upgrade or Add?': 8 rapid scenario cards (tiny blog, Black Friday spike, need redundancy, max-tier server already...), player picks Scale Up / Scale Out, timer + streak.

## Mission
Mission: budget-limited; survive a TV spike; vertical-only path fails at the hardware ceiling -> player must realise horizontal is needed (passes with 2+ web servers; LB not yet in palette, so traffic split is DNS round robin-ish penalty). Badge 'Scale Thinker'.
