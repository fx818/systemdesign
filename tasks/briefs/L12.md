# L12 — Divide and Conquer  (users milestone: 8,000,000; source: reference/ch1.txt p.28-32 (Database scaling))

## Story + lesson content
Incident: the master DB is at 95% disk and growing daily. Lesson: vertical DB scaling — RDS with 24 TB RAM, Stack Overflow 2013 10M monthly visitors on 1 master; drawbacks: hardware limits, SPOF risk, high cost; horizontal scaling = sharding: smaller parts, same schema, unique data per shard; user_id % 4 hash to choose shard (Fig 1-21/22); sharding key (partition key) choice — must distribute evenly; challenges: resharding (shard full or uneven -> shard exhaustion -> update function, move data; consistent hashing in Ch.5), celebrity/hotspot (Katy Perry, Justin Bieber, Lady Gaga on one shard -> dedicated shards, further partition), joins & de-normalization. Fig 1-23: sharded DB + NoSQL for non-relational functionality.

## Lab
Lab: shard count knob, sharding key select (user_id / country / signup_date / first_letter_of_name) showing distribution histogram, celebrity event button, reshard button.

## Mini-games
MiniGame 'Shard Router': user IDs fly in; player computes user_id % N and drops into the right shard under time pressure (N changes 4 -> 5 to show resharding pain). Second: 'Pick the Key' — choose sharding keys for scenarios and see hot shards.

## Mission
Mission: survive data growth and a celebrity post at t=50 (needs enough shards + dedicated hot shard/caching). Badge 'Shard Lord'.
