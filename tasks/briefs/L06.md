# L06 — Memory Lane  (users milestone: 300,000; source: reference/ch1.txt p.14-17 (Cache))

## Story + lesson content
Incident: every page load hits the DB repeatedly; p95 latency 2.4s; users complain the feed is slow. Lesson: cache = temporary in-memory store for expensive/frequent responses; cache tier: faster than DB, reduces DB load, scales independently; read-through flow (check cache -> hit return / miss query DB, store, return); Memcached-style API set('key','hi there',3600)/get; considerations: when to use (read-heavy, rarely modified; volatile memory, restart loses data, persist important data elsewhere), expiration policy (too short -> DB reload, too long -> stale), consistency (DB and cache not one transaction; hard across regions — Facebook memcache paper), mitigating failures (SPOF definition; multiple cache servers across data centers; overprovision memory), eviction (LRU most popular, LFU, FIFO).

## Lab
Lab: TTL slider, cache size slider, eviction select (LRU/LFU/FIFO), kill cache button (SPOF demo), cache-hit meter, DB load meter, stale-data indicator.

## Mini-games
MiniGame 'Evict!': a 4-slot cache, a stream of key accesses; player predicts which key gets evicted under LRU (then LFU, then FIFO rounds). Second mini-game 'TTL Goldilocks': pick TTL per data type (profile pic, like counter, stock price, terms of service).

## Mission
Mission: bring p95 under 200ms and DB load under 70% within budget; a cache node crash at t=45 tests SPOF (needs 2 cache nodes). Badge 'Cache Money'.
