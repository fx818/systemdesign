# L11 — Eyes on the System  (users milestone: 5,000,000; source: reference/ch1.txt p.26-28 (Logging, metrics, automation))

## Story + lesson content
Incident: 'Something is wrong' — at 3 AM the Pager fires; nobody knows which server. Lesson: small sites: nice-to-have, large business: essential; logging (error logs per server or aggregated centrally for search); metrics: host-level (CPU, memory, disk I/O), aggregated (whole DB tier, cache tier performance), key business (DAU, retention, revenue); automation: CI verifies each check-in automatically, catch problems early; automate build/test/deploy. Fig 1-19: message queue + logging/monitoring/metrics/automation tools (one DC shown).

## Lab
Lab: dashboard with toggles to add logging aggregation / metrics / CI; chaos events produce signals only visible when tooling is enabled.

## Mini-games
MiniGame 'Incident Detective': a mystery outage; player investigates centralised logs (searchable list), host metrics charts and business metrics to pick the root cause from 4 suspects (it's a full disk on web-3). Second: 'Metric Sorter' bins (host / aggregated / business).

## Mission
Mission: run a deploy day: with CI + monitoring the bad deploy is caught; without tools uptime suffers. Badge 'Detective'.
