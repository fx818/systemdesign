# L05 — Copy That  (users milestone: 100,000; source: reference/ch1.txt p.11-14 (Database replication))

## Story + lesson content
Incident: the single DB box hiccups, everything stops; Maya panics about losing photos. Lesson: master/slave (we'll say primary/replica in UI but mention the book's master/slave terms); master = writes only, replicas = reads only; insert/delete/update -> master; reads >> writes so more replicas; advantages: performance (parallel reads), reliability (typhoon/earthquake -> data preserved), high availability; failures: only replica down -> reads to master temporarily then replace; multiple replicas -> redirect; master down -> promote replica, data may be stale -> recovery scripts; multi-master/circular mentioned as advanced. Then the full Fig 1-6 flow: DNS->LB IP->LB->server1/2->read from replica, writes to master.

## Lab
Lab: replicas 0-4 knob, read/write ratio slider, kill replica / kill master buttons showing promotion and stale-data warning.

## Mini-games
MiniGame 'Query Router': SQL statements fly in (SELECT, INSERT, UPDATE, DELETE, SELECT JOIN...), player drags each to Primary or Replica; mistakes shown as data corruption/overload.

## Mission
Mission: master dies mid-mission (t=30), a replica dies (t=60); keep reads served and writes recovered. Badge 'Replicator'.
